# Electronic_Scram 数据包与按键说明

本文根据当前 `Send/User/remote_link.c`、`Send/User/my_main.c` 和 `Receive/User/remote_link.c` 编写；串口配置以 Keil 工程实际引用的 `Core/Src/usart.c` 为准。

## 1. 发送的是什么数据包

发送端发送的是**固定 3 字节的自定义二进制急停状态帧**，格式为 `A5 5A KEY`。不是字符串，也不是只在按键按下时发送一个按键编号。

- 无线模块：发送端、接收端均使用 `E34-2G4H27D`。
- 发送接口：发送端 `USART3`（`huart3`，TX 为 PB10）。
- 接收接口：接收端 `USART3`（`huart3`，RX 为 PB11）。
- 两端串口参数：115200 波特率、8 位数据位、1 位停止位、无奇偶校验、无硬件流控。
- E34-2G4H27D 模式脚固定为 `M0=0`、`M1=0`，使用正常透传模式。发送端 M0/M1 为 PB14/PB15，接收端为 PB0/PB1。
- 固件不写入模块配置：使用前需通过外部工具将两端模块的 UART 配置为 **115200、8N1**，并保持信道、空中速率等无线参数一致，使用透传，关闭会附加额外字节的输出选项。更换模块后不能假定出厂参数与固件一致。
- 状态改变后，在主循环中尝试发送；状态不变时，每隔约 100 ms 发送一帧，作为心跳。主循环末尾延时 1 ms。
- `KEY` 只包含四路按键的高低电平位图，不包含序号和 CRC。

## 2. 数据包格式

现在使用固定 **3 字节** 的二进制数据包，只发送帧头和四路按键的电平位图：

```text
A5 5A KEY
```

| 字节偏移 | 长度 | 内容 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 字节 | `A5` | 帧头第 1 字节 |
| 1 | 1 字节 | `5A` | 帧头第 2 字节 |
| 2 | 1 字节 | `KEY` | 四路按键电平位图，仅 bit0～bit3 有效，bit4～bit7 为 0 |

`KEY` 只表示当前四路输入的高低电平，不包含序号、CRC 或其他字段。发送端每次状态改变发送一帧；状态不变时约每 100 ms 发送一帧。

`KEY` 直接表示 PA0～PA3 的原始电平：输入高电平时对应位为 `1`，输入低电平时对应位为 `0`。具体的按下／断开含义由外部接线和上拉／下拉电路决定。

```text
A5 5A 00   四路均为 0
A5 5A 01   开关 1 为 1，其余为 0
A5 5A 05   开关 1、3 为 1
A5 5A 0F   四路均为 1
```
## 3. 包含哪些按键／开关

当前代码采集 **4 路独立的急停开关输入：PA0、PA1、PA2、PA3**。源码没有定义它们对应的实体面板名称或机器人名称，下面按引脚顺序称为“开关 1～4”。

| 文档称呼 | 发送端输入引脚 | `KEY` 中对应位 | 位掩码 | 接收端对应输出引脚 |
| --- | --- | --- | --- | --- |
| 开关 1／急停 1 | PA0 | bit0 | `0x01` | PA15 |
| 开关 2／急停 2 | PA1 | bit1 | `0x02` | PB3 |
| 开关 3／急停 3 | PA2 | bit2 | `0x04` | PB4 |
| 开关 4／急停 4 | PA3 | bit3 | `0x08` | PB5 |

KEY 现在发送原始输入电平；输入采用何种有效电平取决于外部接线：

- 输入为高电平：开关未闭合／急停未按下，对应协议位为 `0`。
- 输入为低电平：开关闭合／急停按下，对应协议位为 `1`。
- 接收端对应输出：协议位为 `1` 时输出高电平，为 `0` 时输出低电平。

发送端实际计算方式为：

```c
// sw_bits 的 bit0～bit3 分别记录 PA0～PA3 是否为高电平。
KEY = sw_bits & 0x0F;
```

注意：`Send/User/my_main.c` 实际将这四个输入配置为 `GPIO_NOPULL`，没有启用 MCU 内部上拉。上述高低电平含义依赖外部上拉及实际接线。

四个位可以同时置位，因此支持多路同时按下：

| 开关状态 | `KEY` 数值 | 二进制 bit3～bit0 |
| --- | --- | --- |
| 全部未按下 | `0x00` | `0000` |
| 仅开关 1 按下 | `0x01` | `0001` |
| 仅开关 2 按下 | `0x02` | `0010` |
| 仅开关 3 按下 | `0x04` | `0100` |
| 仅开关 4 按下 | `0x08` | `1000` |
| 开关 1、3 同时按下 | `0x05` | `0101` |
| 四路全部按下 | `0x0F` | `1111` |

当前帧只携带这四路开关的实时状态，没有单独的长按、短按、双击事件，也没有摇杆、方向键或其他手柄按键数据。发送端当前未实现按键消抖；`RemoteLink_ForwardRawFrame()` 为空函数，不会额外转发其他数据包。

## 4. 数据校验

当前 3 字节协议不包含 CRC 校验。接收端只检查帧头 `A5 5A`，随后直接读取 `KEY` 字节。

## 5. 完整报文示例

```text
A5 5A 00   四路均未按下
A5 5A 01   PA0 为高电平，其余为低电平
A5 5A 02   PA1 为高电平，其余为低电平
A5 5A 04   PA2 为高电平，其余为低电平
A5 5A 08   PA3 为高电平，其余为低电平
A5 5A 05   PA0、PA2 为高电平
A5 5A 0F   PA0～PA3 全部为高电平
```
## 6. 接收端处理与状态保持

接收端先寻找帧头 `A5 5A`，再收第 3 字节。收到 `A5 5A` 后，第 3 字节作为 `KEY` 更新四路状态。

- 只使用 `KEY` 的低四位，高四位忽略。
- 上电尚未收到有效帧时，四路输出均为高电平，按代码设计进入全部急停状态。
- **不做通信超时检测**。收到有效帧后，即使后续没有收到数据，也持续保持最后一次有效状态，不会因失联自动改变输出。
- 再次收到有效帧后，按该帧的四路开关状态更新输出。
- PB6、PB7、PB8、PB9 在当前输出函数中始终置低，不对应额外的四个按键。
